# Feature status

This release carries the language below from source through NeuraIR, optimization, neuron conversion, and the `.nvr` image to execution in the Neura Virtual Machine. Every feature marked supported compiles to a standalone image, runs under `neura run`, and has end-to-end tests; the [release checklist](../Release.md) maps each one to its tests. See [Tooling](Tooling.md) for the commands.

## Application platform development

[HTML factories](../apps/Html.md) construct views in ordinary NeuraIR and NVR, with typed holes and external template sources. [Stylesheets](../apps/Css.md) are module-level constants, inline or from files, with CSS-module names, bundled imports and assets, and a fixed link order that the build writes beside the image. [State and components](../apps/Components.md) are library code in `Std.Ui`: `ui.State<T>` of deeply immutable values, subscriptions, components with slots, and roots whose turns render and commit over a `ui.Host`, tested on the in-memory `Std.Ui.ModelHost`. Commands (`Std.Ui.Commands`), the router (`Std.Ui.Routing`), validated forms (`Std.Ui.Forms`) and controls over real elements (`Std.Ui.Controls`) are implemented and tested on the model host, and a refused commit rolls back the turn's mounts. A root's commit is validated and reconciled by library code that issues the host operations in their fixed order; templates are checked to be render-compatible (`E1010`); a child component that renders alone commits only its own nodes, and a retained component's nodes are reused without expanding its views again. `Std.Web.mount` runs a component tree in a browser page over the runtime's UI services, with commands, the router (hash or history routing, back and forward), forms with focus and controls, checked end to end in headless Chromium and Firefox, together with every event kind, input overflow, reset and the mount errors; a page can call a Neura backend through `Std.Net.Http.Fetch`; and `scripts/build-web-bundle.py` bundles an application with its stylesheets for any static host ([Your first Neura web app](../apps/WebApp.md)). `neura build --project --target` builds the web, server and desktop targets of a `neura.toml` project into verified, reproducible bundles, and `neura run` runs server and desktop bundles ([Projects and bundles](../apps/Projects.md)). `neura new` writes a project from the `fullstack`, `web`, `server` or `desktop` template ([Your first Neura project](../apps/FirstProject.md)). `neura package` wraps server and desktop bundles for delivery. `neura dev` serves, reloads and restarts a target while its sources change. Package closures are enforced (`E1030`), and `neura check` understands a project; the editor does not yet. Budget B-W5 (input to commit, 8 ms) is missed in the browser: a row change of a 1,000-row list takes about 130 ms at the median ([Apps030](../design/Apps030.md#budgets)). The desktop host; derived codecs for `FrozenList`, contracts, and the render check of component `render` functions are not implemented.

The browser runtime runs an image in a page under Node, headless Chromium and headless Firefox: `nvm.wasm` at tiers 0 to 2, waits and timers without polling, and the [UI and history host services](../runtime/Providers.md#ui-services) with their commit and event encodings. `Std.Web.mount` drives these services from Neura, under hash or history routing. `neura.http.fetch` is served in the browser through the browser's own `fetch`, with the library binding `Std.Net.Http.Fetch` ([HTTP fetch](../runtime/Providers.md#http-fetch)); a native `neura run` does not serve it yet. `scripts/build-web-bundle.py` assembles web bundles holding an image, its stylesheets and assets and the runtime, refuses images that import services a web target cannot have, and has the browser check every module by its digest. Recording and replay in the browser, gesture actions, and Safari are not implemented yet.

## Open language decisions

These are not decided. For most of them the compiler rejects or does not offer the construct, so no program depends on a choice. The exception is shadowing: the compiler accepts a nested declaration of a name and hides the outer binding, so a program that does this depends on the current behavior.

| Area | Open decisions |
| --- | --- |
| Core | Whether shadowing stays allowed, Unicode identifiers |
| Types | Type inference beyond local bindings and the arguments of a call, static non-nil types, nested enum patterns, match guards, value members of payload enums (and so records holding them), compiler-owned derivation of JSON codecs |
| Generics | Inference of the type arguments of `new` and of enum constructors, which stay written or target-typed; generic class inheritance, variance |
| Modules | Package-level resolution, and with it the boundary of `#Internal`, which is a directory tree until packages exist |
| Lifecycle | Ownership, alias safety beyond the shared-object rule below, definite initialization of `let` fields (`last` fields are checked), failure cleanup |

## Frontend conventions

- Identifiers use ASCII letters, digits, and underscores. Source strings and comments support UTF-8. String and character literals support the escapes `\n`, `\r`, `\t`, `\0`, `\\`, `\'`, `\"`, `\xHH` and `\u{H}`; a string's bytes must be valid UTF-8 (E0268-E0270).
- Decimal integer literals default to `int32` and decimal floating-point literals default to `float64`. A numeric context selects a literal of a different width; [Numbers](Numbers.md) specifies ranges and rounding.
- Keywords such as `for`, `in`, `as`, `is`, `nil`, `enum`, `match`, `interface`, `implements`, `and`, `or`, `not`, and `typeof` cannot name bindings. `last`, like `scope`, `spawn`, and `select`, is a contextual word and stays a valid name: it declares only when an identifier follows it ([Core language](CoreLanguage.md#source-and-bindings)).
- Every declaration ends with `;`, including a function, overload group, class, interface, or module member whose body ends at `}` or `)`; statement blocks take none. A missing `;` is error `E0201`, and `neura check --fix` inserts it.
- An exported instance field may have `| get:` and `| set:` accessor clauses ([Types](Types.md#accessors)). Inside the declaring class a bare field name or `instance.field` is the storage; any other receiver, a subclass, and code outside the class call the accessors, and a read-modify-write evaluates its receiver once, then gets, computes, and sets. A get-only field is read-only outside its class (`E0510`) and a set-only field write-only (`E0515`). An unmarked accessor resolves statically and cannot be overridden; `| get.virtual:` and `| set.virtual:` make a slot that a subclass overrides with `let.override` ([Polymorphism](Polymorphism.md#virtual-accessors)), and an interface requires a property with `| get;` ([Polymorphism](Polymorphism.md#interface-properties)).
- A `let` or `const` local binding requires an initializer. A `last` local or instance field may omit it and is then assigned exactly once on every path before it is read, checked by the definite-assignment rules of [Core language](CoreLanguage.md#deferred-assignment). Decision for 0.2.0: `last` is the only deferred form, `const` stays for module, file, and static constants, and a deferred `last` binding outside a function body or instance field is an error. A nonempty collection literal without an expected type infers an array, and an empty literal requires an expected collection type.
- The examples initialize some fields after construction. The frontend accepts that pattern for `let` fields; reading a field before any store is a runtime fault. A `last` field without an initializer must be assigned by every constructor ([Object lifecycle](ObjectLifecycle.md#last-fields)).
- A target-typed `new` takes the expected type of its value: a binding or field annotation (including an element of a typed destructuring declaration), the declared type of an assignment's destination, a function's declared result type for `return`, a parameter for a call argument once the callee is known (among overloads it is a contextual argument), and the element type of an expected collection or the type of an expected conditional. There is no other inference: `let a = new;` is E0420 ([Object lifecycle](ObjectLifecycle.md#target-typed-new)).
- A destructuring list after `=` has one value per name, evaluated left to right before any name is bound. The typed and listed forms are allowed where destructuring already was, in blocks and at file level, not as module or class members ([Types](Types.md#typed-and-listed-destructuring)).
- Anonymous class identity: a fields-only body, whose members are all exported, typed `let` instance fields without accessor clauses, is one class wherever it is written, identified by its fields' order, names, and types; field initializers are not part of its identity. Any body with a method, lifecycle function, static member, cast, base, or interface, or with a `const` or `last` field or an accessor clause, is a class of its own per occurrence and accepts every member a declared class accepts. A fields-only class runs the field initializers of the body in the annotation of the binding that `new` initializes, or of the body written after `new`; initializers anywhere else are rejected. A fields-only class is the same class across separately compiled NeuraIR modules ([Types](Types.md#anonymous-classes)).

## Backend conventions

[Neuron conversion and execution](../Backend.md#semantic-decisions) records how conversion implements each rule.

- Integer overflow, a zero divisor, `MIN / -1`, and an out-of-range conversion trap with reason 1. Division truncates toward zero. Each class of trap ends the run with its own process status ([Errors](Errors.md)).
- A negative index traps with reason 2; a list modified during for-each traps with reason 5.
- The entry point is the unique override of `Std.Program.Entry.main`, run for the one module that inherits it and that no other module inherits ([Modules](Modules.md#interfaces-and-inheritance)). `Ok` is status 0, `Failure` 1, and `Status(n)` is `n` for 0 through 255; any other `n` traps. The named variants from `SeriousFailure` (2) to `FileSizeExceeded` (153) have fixed statuses ([Modules](Modules.md#program-entry)). The built-in `SysIo` and `Test` modules are retired, and importing either is an error that names its replacement.
- An instance field without an initializer starts uninitialized, and reading it before a store faults. Static fields follow the preparation and first-use rules in [Static initialization](Types.md#static-initialization). Construction and `destroy` follow the order in [Object lifecycle](ObjectLifecycle.md).
- In an NVR 1.5 or later image with a `TRNS` table, live frames of every task count toward `--max-heap-cells` (one cell per frame plus one per slot), as do task records and open scopes; `--max-frames` bounds each task's depth. Images without tasks keep their accounting.
- `Console.print_line` traps with reason 3 when the write fails, and a failed `Std.Test` assertion is a message trap with reason 3.
- Tuples and payload enums are stored inline as value words, boxed only where the runtime carries one word ([Backend](../Backend.md#tuples-and-enums-are-words)). A value type that contains itself is `E0448` and one of more than 64 words is `E0449`, both reported on the specialized program before optimization.

## Editor tooling candidate

Neura 0.3.0 provides LSP, formatting, exact test discovery/reporting, mapped-block line coverage, DAP source debugging, and graph inspection, first shipped in the `0.2.1-rc.2` candidate. See [Tooling](Tooling.md#editor-tooling) for interfaces and present limits. The candidate also covers incomplete-buffer formatting, declaration/import completion, promoted-name completion, readable documentation hovers, and valid outline ranges with editor protocol regression tests. The editor tooling changes no language syntax or runtime semantics.
