# E1030: module not available to this package or target

In a project, a module belongs to the package whose root holds its file, and a package may import its own modules, the standard library, and the modules of the packages in its `depends` closure. `neura build --target` and `neura check` of a file inside a project report `E1030` at an import of a module of any other package: this is how server code is kept out of a browser bundle, because the `ui` package does not depend on `server`. Add the package to `depends`, or move the shared code to a package both depend on, such as `contracts`.

<!-- diagnostic: not reproducible: the rule is about the packages of a project, which a single source file does not have -->
<!-- example: fragment: the ui package may import the contracts package because it depends on it -->
```toml
[packages.ui]
root = "ui"
depends = ["contracts"]
```
