# E0546: hooked class reference at a bodyless function

A reference of a class that has a hook, or of an interface or `class` type that such a class implements, carries its class policy beside the handle. A host binding, a built-in kernel or a foreign function has no place for that policy on its other side, so none of them can take or return such a reference. The check runs on the specialized signatures of the linked program.

<!-- diagnostic: not reproducible: no bodyless function of the standard library takes or returns a class, an interface or a type parameter that a program can instantiate with a hooked class, and C imports map no C type to a class; the compiler's tests build the program in memory -->

Pass an identifier or a plain data class across the boundary instead:

<!-- example: check -->
```neura
let Session = class (
    | set: value;

    export let id: int64 = 0;
);

let describe = func(session: Session) -> int64 {
    return session.id;
};
```

See [class hooks](../design/Hooks030.md#representation).
