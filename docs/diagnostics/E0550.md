# E0550: event emitted under a monitor guard

`Std.Events.Event.emit` runs every handler synchronously, inside the call. Under a monitor guard, the handlers would run while the guarded state is locked, and a handler that reaches the same monitor would block or trap. So `emit` is not called in a `#Synchronized` method, in a lambda passed directly to `Guarded.with`, or in a function either of them reaches through calls the compiler resolves. A call through a function value is not followed, so the check covers the known call graph and is not a proof. The error points at the `emit`, or at the call that reaches it, and labels the `#Synchronized` tag or the `Guarded.with` call.

<!-- example: error: E0550 -->
```neura
let events = import:Std.Events.Event;

#Synchronized
let Account = class (
    let balance: int = 0;
    let changed = new events.Event<int>();
    export let deposit = func(amount: int) {
        balance = balance + amount;
        changed.emit(balance);
    };
);
```

Commit the change, leave the guard, then emit:

<!-- example: check -->
```neura
let events = import:Std.Events.Event;
let guards = import:Std.Concurrent.Guarded;

let deposit = func(state: guards.Guarded<int>, changed: events.Event<int>, amount: int) {
    last balance = state.with<int>(func(value: int) -> int => value + amount);
    changed.emit(balance);
};
```

See [the standard library specification](../lang/Stdlib.md#20-stdevents).
