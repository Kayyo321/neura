# E0475: scoped resource leaves its using block

A resource bound by `using` is closed when its block is left, so it may not leave the block. It is not returned, stored in a field, a global, an element, a list or a binding of an outer block, sent on a channel, captured by a function value that a callee retains, captured by a task that is not joined inside the block, or passed to a parameter whose [retention summary](../IrOptimization.md#effect-summaries) is "retained elsewhere" or unknown. A value whose summary says it retains the resource, such as a reader constructed over it, is scoped in the same way. A `spawn` that captures the resource is accepted inside a `scope` block that is itself inside the `using` block, because the scope joins its tasks before the close. The check reads the retention summaries of the linked program; an alias that the acquisition kept elsewhere is not tracked.

<!-- example: error: E0475 -->
```neura
let closeable = import:Std.Io.Closeable;
let.promote _ = import:Std.Core.Result;
let.promote _ = import:Std.Core.Unit;
let Resource = class implements closeable.Closeable (
    export let close = func -> Result<Unit> => Result<Unit>.Ok(Unit.Value);
);
let keep = func() -> Result<Resource> {
    using (source = new Resource()) {
        return Result<Resource>.Ok(source);
    }
};
```

Use the resource inside the block, and return what it produced:

<!-- example: check -->
```neura
let closeable = import:Std.Io.Closeable;
let.promote _ = import:Std.Core.Result;
let.promote _ = import:Std.Core.Unit;
let Resource = class implements closeable.Closeable (
    export let close = func -> Result<Unit> => Result<Unit>.Ok(Unit.Value);
);
let keep = func() -> Result<string> {
    using (source = new Resource()) {
        return Result<string>.Ok("used");
    }
};
```
