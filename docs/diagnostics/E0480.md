# E0480: conflicting inferred type arguments

A call of a generic function without written type arguments infers them from its arguments. Every argument that gives a type parameter must give it the same type. Two different types are an error, also when one is assignable to the other: inference computes no common base and never widens a number.

<!-- example: error: E0480 -->
```neura
let Animal = class ();
let Dog = class : Animal ();
let same = func<T>(a: T, b: T) -> T => b;
let use = func(dog: Dog, animal: Animal) -> Animal => same(dog, animal);
```

Write the type arguments:

<!-- example: check -->
```neura
let Animal = class ();
let Dog = class : Animal ();
let same = func<T>(a: T, b: T) -> T => b;
let use = func(dog: Dog, animal: Animal) -> Animal => same<Animal>(dog, animal);
```

Numeric literals that are the only source of a type parameter each give their default type, `int32` or `float64`, and those must agree too: `same(1, 2.5)` is this error, and `same(1.0, 2.5)` is not.

See [Polymorphism](../lang/Polymorphism.md).
