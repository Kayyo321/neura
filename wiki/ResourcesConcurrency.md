# Resources and concurrency

[Wiki home](https://github.com/Kayyo321/neura/wiki) · [Language overview](https://github.com/Kayyo321/neura/wiki/Overview) · [Feature status and open decisions](https://github.com/Kayyo321/neura/wiki/Status)


[Object lifecycle](https://github.com/Kayyo321/neura/wiki/ObjectLifecycle) proposes `init`, `deinit`, and explicit `destroy`, but aliasing and cleanup on failure remain unresolved. A resource API must define who owns a handle, when it is closed, and what happens if closing fails. Until then, do not assume scope-exit cleanup, garbage collection, or safe access through aliases after destruction. [resources.nra](https://github.com/Kayyo321/neura/blob/main/examples/guide/resources.nra) illustrates the intended lifecycle with an in-memory class; it is not a file API. A `scope` block waits for tasks; it does not close resources. The scoped helpers that open a resource, run a body, and close the resource exactly once are described in the [standard library](https://github.com/Kayyo321/neura/wiki/StandardLibrary) page.

Concurrency is specified in [Concurrency](https://github.com/Kayyo321/neura/blob/main/docs/lang/Concurrency.md), which also records which parts exist at this commit and which are in progress. A `scope` block starts tasks with `spawn` and waits for them on every exit ([Core language](https://github.com/Kayyo321/neura/wiki/CoreLanguage#tasks-scopes-and-select)). A task's mutable state is its own: tasks cannot share objects, arrays, or lists, and a value given to another task must have a [transferable type](https://github.com/Kayyo321/neura/wiki/Types#scope-bound-and-transferable-types). Tasks share work through typed, bounded channels and `select`, and share state through `AtomicInt64`, `Semaphore`, and `Guarded<T>` from `Std.Concurrent`; the preferred shape is state owned by one task and reached over a channel. Cancellation is cooperative and scoped. It wakes a task that is parked on a channel operation or a timer and never interrupts a running one, and a scope that was cancelled still waits for its tasks. A runtime failure in any task ends the run without cleanup ([Errors](https://github.com/Kayyo321/neura/wiki/Errors#tasks)). The memory model, the cancellation rules, and the stages' contracts are in [Concurrency](https://github.com/Kayyo321/neura/blob/main/docs/lang/Concurrency.md).

[concurrency/service.nra](https://github.com/Kayyo321/neura/blob/main/examples/concurrency/service.nra) is a complete program that runs with the default capabilities. It shows three things, each with its output:

- State owned by a task. `price_owner` holds a price table that no other task can reach. Other tasks send it `Put` and `Get` requests on a channel, and a `Get` carries the channel on which to reply. Three tasks ask for a price, and the program prints `tea 3, cake 5, soup -1`.
- A cancellable operation. `first_answer` starts three searches at different speeds, takes the first answer, and cancels the scope with its `Scope` handle. The slower searches ask `Cancellation.requested()` between steps, return early, and are waited for before the scope exits, so nothing they hold outlives the call. The program prints `fast answered; the others stopped early: true`.
- Safe shared state. Three tasks count page visits in a table behind a `Guarded` handle. The table can be reached only inside `with`, one task at a time, and nothing that refers to it can leave. The program prints `home 400, about 200`.
