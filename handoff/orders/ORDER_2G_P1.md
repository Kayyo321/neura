## Background

Stage: NVM runtime, tier 2 (`src/nvm/tier2.hpp`, `tier2.cpp`, `tier2_steps.inc`, the dispatcher in `machine.cpp`, `src/jit`). Read `docs/runtime/NVM.md` sections "Execution tiers", "Native compilation", "Controls", and the code they describe, before anything else.

Today a tier 2 **region** is a set of lifted blocks of one function joined at their exits. It ends at every call, return, allocation, and at every state operation or kernel the region cannot do itself; control then returns to the dispatcher, which runs one block at a time (tier 1 or tier 0) until a region entry is reached again. Measured on this branch at the long benchmark sizes, Neura is 3.6 to 470 times slower than Java (geometric mean 45): programs whose steps stay in regions of integer code are in single digits, programs that leave regions are in the tens and hundreds (`sha256` 470, `nbody` 245, `text-split` 126, `parse-results` 114, `object-churn` 103, `closures` 85, `binary-trees` 73).

The plan for this milestone is **function programs**: the unit of compiled code becomes the whole function; calls, returns, allocations, state operations and kernels become operations of the program (first in the portable region interpreter, then in native code), so that control leaves compiled code only to deoptimize, to trap, at a host request, or at a scheduling point. The slot map stays the deoptimization map: at every point where compiled code can leave, the canonical frame (`frames_`, slots and initialized flags, `frame.block`), the step counters and the heap are exactly what the reference evaluator would have.

The invariants of WORK_RULES.md hold for the design: identical exits, traps (kind, reason, detail, function, block, callers), `steps`, `function_steps`, `peak_heap_cells`, host requests, output and traces at every tier; no added step; nothing from an image trusted unproven.

## Part B — the design document

Write `wo2g/design.md`. It must be exact enough that an implementer who has not read this order can implement it without making a design decision, and that a reviewer can check each rule against the code. No code snippets longer than a declaration; name the existing functions and files each rule touches (with line numbers at b9ef537).

Required contents:

1. **What exists.** How regions are formed, entered, run, left and invalidated today: data structures (`tier2::Region`, programs, ops, registers, the three analyses rooted at the entry, undo log, checkpoints, the refuse-entry mechanism, region counts), the dispatcher loop, the budget and poll accounting, how `done`/`steps_`/`function_steps_` are flushed, how `NEURA_TIER_CHECK=1` and `=2` hook in, how native code is produced from a region program and how it leaves. One page.
2. **Unit and entries.** A function program covers every block of a function. Entries: the function's entry, loop heads, and the resume block of every call (where a callee returns to). For each analysis that is rooted at program counter 0 today (`entry_reads`, `entry_canonical`, the width/canonical facts), how it becomes per-entry, and what facts reset where (the return-slot register after a call).
3. **Formation.** When a function gets a program (thresholds, in terms of counts that do not depend on time), that all hinted blocks of the function are proven at formation so that cold blocks are not stubs, what happens to a block that cannot be lifted (a stub that deoptimizes there), the cost bound of formation, and invalidation.
4. **New operations**, each with: preconditions; exactly which canonical state it reads and writes and in which order; what it does to `done`, `steps_`, `function_steps_`, the budget and the poll count; every way it can fail and, for each, whether it deoptimizes before any effect (the block is re-run by tier 1 from block-entry state) or traps in place (after write-back, `frame.block`, step flush and step charge); and the existing function it must be bit-for-bit equivalent to.
   - **Call** (direct, dispatch, closure): commit of assignments, the frame limit, the frame arena's growth, task images (frame cells are charged to the heap there), `push_frame`, what `frame.block` of the caller holds while the callee runs, traps' `callers` list.
   - **Return**: callback boundaries (`boundary` frames), the empty stack, the last frame of a task, open scopes, the return slot and block, the result's initialized flag.
   - **AllocObject, AllocCollection, RepeatCollection**: the limit checks in today's order, the collection that may run (a safepoint: which registers hold references and how they are rooted — the canonical frame must be written back first, or the registers enumerated), handle assignment, cell accounting.
   - **State operations** (each kind in `State::state()`): which are simple enough to be an inline check + load/store later in native code, and which stay helper calls; for helper calls the rule "write back, set `frame.block`, flush `done`, charge the step, then call; a fault is the trap in place, never a re-run".
   - **Kernel calls and text building**: helper calls under the same rule.
   - **Host requests, scheduling points, polls**: where compiled code must leave, and how it re-enters at the resume entry.
5. **Checkpoints and deoptimization.** Where checkpoints are (function entry, loop heads, every resume block), what a deoptimization restores, why a deoptimization inside a callee leaves the callers' frames canonical (they are canonical at every Call by rule 4), and the undo log's scope.
6. **The interpreter first.** How the portable region interpreter executes a function program across calls (one interpreter activation per frame, or a loop over frames; recursion depth; how "left" unwinds), so that it is the reference for the native code of the next order.
7. **What the native code of the next order needs from this one** (compiled-to-compiled calls with a bound on nested native activations, one global `done` counter, inline allocation fast path) — interface only.
8. **Interactions.** `NEURA_TIER_CHECK=1` (cannot check these operations: they compile as deoptimizations under it), `NEURA_TIER_CHECK=2` (sync points: where must `shadow_entering`/`shadow_returned` be called now that compiled code returns rarely? propose additional sync points, for example every N calls or at every loop-head checkpoint, with their cost), `--profile` (`function_steps`), record/replay, the debugger and coverage (both run at tier 0 and must stay there), tasks and the scheduler quantum, parallel items, fleets and graph devices, `--tier-stats` (which lines change meaning; the lines `scripts/bench-wall.py` and `scripts/tier-boundary.py` parse must keep their format).
9. **Order of implementation** as a list of steps, each independently testable and each leaving every existing test passing, with the tests that step adds (each must fail without it) and the identity runs it needs. The first step must be the smallest change that gets a Call and a Return inside a program for one function shape.
10. **Risks and open questions** for the lead, each with the evidence that raised it and your recommended answer.
