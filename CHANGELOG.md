# Changelog

This file records the changes in each version of Neura that a user of the language, the `neura` command, the standard library, or the `.nir` and `.nvr` formats can observe. Its layout follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

Versions are numbered `MAJOR.MINOR.PATCH`. Before `1.0.0`, a minor version may change or remove existing behavior, and its entry lists each such change under **Changed** or **Removed**. The `.nir` and `.nvr` formats carry their own version numbers, which the [NeuraIR format](docs/NirFormat.md) and [NVR format](docs/runtime/NVR.md) pages define.

A pull request that changes observable behavior adds a line to **Unreleased** under one of these headings:

| Heading | For |
| --- | --- |
| Added | New syntax, library members, commands, options, or format features. |
| Changed | Existing behavior that now differs, including a diagnostic or exit status that programs or scripts may depend on. |
| Deprecated | Behavior that still works and is scheduled for removal. |
| Removed | Behavior that no longer exists. |
| Fixed | Behavior corrected to match its specification. |
| Security | Fixes for vulnerabilities reported under the [security policy](SECURITY.md). |

## Unreleased

### Added

- `Std.Core.Character`: Java's `Character` over Unicode 17.0.0 in snake_case, as module functions on `uint32` code points and as an immutable value class holding one scalar value, with `equals`, `hash_code` (the code point), `compare_to`, and `to_string`. Categories, bidi classes, case properties and simple and full case mappings, digits and numeric values, identifier and emoji properties, surrogates and UTF-16 helpers, and character names: `get_name` (Java's names, with its block form for the CJK unified ideographs, Hangul syllables, and other unnamed code points), `unicode_name` (the Unicode Name property, generated for Hangul syllables and the patterned ranges), and `code_point_of` and `try_code_point_of`, which accept both kinds of names. The 34,594 stored names are front-coded with a word dictionary in 314 KB of source, which only programs calling these members carry. `Std.Core.UnicodeScript` and `Std.Core.UnicodeBlock` give the Script and Block properties. `scripts/generate-unicode-tables.py` writes the tables, and `tests/stdlib/character` checks every code point, the names against Perl, Python, ICU, and a JDK ([Stdlib](docs/lang/Stdlib.md#85-character)).
- `Std.Crypto` contracts: `SecretMemory<T>`, `SymmetricKey<Alg>`, `PrivateKey<Alg>`, `CryptographicPrimitive<Alg>`, `StreamingDigest<D>`, `ExtendableOutput<D>`, `AeadCipher<Key, Nonce, Tag>`, `Signer`, `Verifier`, `KeyEncapsulation` and `KeyStoreProvider<KeyHandle>`, and the `Algorithm` enum ([Stdlib, section 21](docs/lang/Stdlib.md#21-stdcrypto), [design](docs/design/Crypto030.md)).
- `Std.Crypto.Core`: `SecretBytes`, `Secret<T>` and `SecretKey<Alg>` (redacted text, `wipe`, constant-time `ct_equals`; `SecretBytes` and `SecretKey` can move retained bytes into Linux locked host buffers), `ConstantTime` (`ct_eq`, `ct_eq_uint32`, `ct_less`, `ct_select`, `ct_select_bytes`, branch-free in source), and the process-wide `CryptoPolicy` (`Modern`, `Fips140_3`, `Cnsa2_0`) that primitives check when created ([Stdlib, section 21.2](docs/lang/Stdlib.md#212-stdcryptocore)).
- `Std.Crypto.Hash`: `Sha2` (SHA-224 to SHA-512/256; `Sha256` shares the kernel of `Std.Digest.Sha256`), `Sha3` (SHA3, SHAKE, cSHAKE, TurboSHAKE), `TupleHash`, `Blake3` (hash, keyed hash, key derivation, XOF) and the append-only `MerkleTree<H>` with RFC 9162 inclusion and consistency proofs, each checked against generated or published known answers ([Stdlib, section 21.4](docs/lang/Stdlib.md#214-stdcryptohash)).
- `Std.Crypto.Mac`: the `Authenticator` interface, `Hmac<H>` over any digest, `Kmac128`/`Kmac256` with their XOF forms, `Poly1305` and `AesCmac`, each with constant-time `verify` that refuses truncated tags ([Stdlib, section 21.5](docs/lang/Stdlib.md#215-stdcryptomac)).
- `Std.Crypto.Kdf`: `Hkdf`, `Pbkdf2`, `Scrypt`, Argon2id (`Argon2`), `Balloon`, PHC strings (`Phc`), `PasswordHash` with `verify_password` and `needs_rehash`, and `Calibration` of Argon2id parameters to a target latency on a supplied clock ([Stdlib, section 21.6](docs/lang/Stdlib.md#216-stdcryptokdf)).
- `Std.Crypto.Symmetric`: `AesGcm`, `AesGcmSiv`, `AesSiv`, `ChaCha20Poly1305` and `XChaCha20Poly1305` as `AeadCipher`s, the STREAM `OnlineCipher` for chunked authenticated encryption, `Ff1` format-preserving encryption, and the hazmat `AesBlock` and `ChaCha20` ([Stdlib, section 21.7](docs/lang/Stdlib.md#217-stdcryptosymmetric)).
- `Std.Crypto.Random`: `Entropy.os_bytes` over the existing entropy service, and `ChaCha20Drbg`, a fast-key-erasure generator seeded from caller bytes or the operating system. `hardware_bytes` (RDSEED/RNDR) and `fork_generation` (fork and VM-clone detection, used by `ChaCha20Drbg.fork_safe`) are stubs until the runtime provides them ([Stdlib, section 21.3](docs/lang/Stdlib.md#213-stdcryptorandom)).
- `Std.Crypto.Asymmetric` and `Pqc` add classical signatures and key exchange, HPKE, ML-KEM, ML-DSA, and SLH-DSA. The hybrid TLS X25519MLKEM768, X-Wing, and composite ML-DSA-65 with Ed25519 have draft and independent reference coverage ([Stdlib, section 21.9](docs/lang/Stdlib.md#219-stdcryptopqc)).
- `Std.Crypto.Pki` verifies signatures by default for certificate paths, CSRs, OCSP and Certificate Transparency. It supports RSA PKCS #1 v1.5 and PSS, ECDSA, Ed25519, Ed448, pure ML-DSA and SLH-DSA, HashML-DSA with SHA-512, and composite ML-DSA-65 with Ed25519 ([Stdlib, section 21.10](docs/lang/Stdlib.md#2110-stdcryptopki)).
- `Std.Crypto.Token` adds typed JWK verification keys, compact JWS and JWE (including RSA-OAEP-256), JWT time claims with a supplied clock, PASETO v4, libmacaroons v1/v2, and Biscuit v3 minting, attenuation, sealing, third-party blocks and bounded Datalog authorization ([Stdlib, section 21.11](docs/lang/Stdlib.md#2111-stdcryptotoken)).
- `Std.Crypto.Enclave` adds a versioned software key store, an envelope engine, and offline AWS Nitro, AMD Milan SEV-SNP, and Intel SGX v3 and TDX v4 evidence verification with authenticated collateral ([Stdlib, section 21.12](docs/lang/Stdlib.md#2112-stdcryptoenclave)).
- `Std.Crypto.Advanced` adds two-field Shamir sharing, ristretto255, hash-to-curve for ristretto255 and P-256/384/521, all five RFC 9591 FROST ciphersuites, all four RFC 9474 RSA blind signature variants, batched OPRF/VOPRF/POPRF for all five RFC 9497 ciphersuites, Merlin transcripts, and single-value and aggregate Bulletproofs ([Stdlib, section 21.13](docs/lang/Stdlib.md#2113-stdcryptoadvanced)).
- Secret-bearing crypto classes use fixed redacted displays. HPKE ciphertext containers and CRLite Bloom layers compare by value. X.509 name equality matches repeated attributes exactly once.
- Named arguments: `schedule("backup", urgent: true)` gives a value to the parameter of that name, after the positional arguments; a named call is evaluated in the order it is written, and one in parameter order builds the image of the positional call. New diagnostics `E0225` (a positional argument after a named one), `E0482` (unknown label), `E0483` (a parameter given two values) and `E0484` (labels on a call through a function value, an intrinsic member, an enum constructor, a variadic function, or a `&T` argument out of order) ([Core language](docs/lang/CoreLanguage.md#named-arguments)).
- Constant defaults: `func(job: string, retries: int = 3)`. The caller inserts the default, which a `.nir` module records as the new NeuraIR attributes `parameter.default` (id 12) and `parameter.default.variant` (id 13), without a format version change. New diagnostics `E0226` (a default on a parameter that takes none) and `E0485` (a default that is not a constant) ([Core language](docs/lang/CoreLanguage.md#default-values)).
- Contextual inference: a call of a generic function infers the type arguments it does not write, from its arguments, its lambdas and its expected type, and an inferred call builds the image of the written call. A lambda may leave its parameters untyped where a function type is expected, `func(a, b) => a + b`. New diagnostics `E0480` (conflicting inferred type arguments) and `E0481` (a lambda that does not fit its function type) ([Polymorphism](docs/lang/Polymorphism.md#type-argument-inference)).
- Extension sets: `let.extension name = func(receiver: T, ...)` declares a function that a file or module enabling it with `let.extensions alias = import:Module;` may call as a member of `T`. Extension functions carry the NeuraIR attribute `function.extension` (id 14). New diagnostics `E0228`, `E0315`, `E0316` and `E0488` ([Modules](docs/lang/Modules.md#extension-sets)).
- Interpolated strings, `$"{name}: {count:>4} items"`: each hole is evaluated once in written order, each specification is checked against its hole's type at compile time with the formatting library's rules and messages, and the text is formatted by `Console.vformat`. New diagnostics `E0227` (a malformed interpolated string) and `E0486` (an invalid specification) ([Core language](docs/lang/CoreLanguage.md#interpolated-strings)).
- `nameof(path)`, the declared name of a declaration as a string constant, which evaluates nothing. New diagnostic `E0487` ([Core language](docs/lang/CoreLanguage.md#nameof)).
- The language server marks the parameter of an argument's label in signature help, shows defaults in hovers, signatures and `neura docs`, completes labels, renames a parameter with its labels, reaches into interpolation holes and `nameof` operands, and lists enabled extension functions among a value's members ([Tooling](docs/lang/Tooling.md#editor-tooling-research-candidate)).

- Guards and nested patterns in `match`: `pattern if condition => result`, variant and tuple sub-patterns, and tuple subjects, `match ([a, b])`. Coverage shows an uncovered value as a pattern. New diagnostics `E0231` (a literal, range, rest or type pattern) and `E0491` (an unreachable arm) ([Types](docs/lang/Types.md#enums)).
- `not`, a reserved word that is `!` spelled as a word at the level of `!`, and `x is not T`, which is `!(x is T)`; both build the image of the `!` form, and `neura fmt` keeps the spelling. `typeof` is now reserved too, so neither word names a binding ([Core language](docs/lang/CoreLanguage.md#expressions)).
- Narrowing in `if` conditions: `if (shape is circle: Circle && circle.radius > 0)` binds `circle` in the later conjuncts and the true branch, and `if (shape is not circle: Circle) { return; }` binds it in `else` and after the `if`. A narrowing `if` builds the image of the `match.is` it stands for. New diagnostics `E0265` (a narrowing outside the top-level conjuncts of an `if` condition) and `E0266` (`is not` with a binding inside an `&&` chain) ([Types](docs/lang/Types.md#narrowing)).
- Character literals, `'A'`, `'\n'`, `'\''` and `'\xFF'`: an integer literal of one byte with the contextual typing of a decimal literal, which is a `byte` without an expected type and builds the image of the decimal literal. New diagnostics `E0260` (a character that is not one byte, or a `\u` escape) and `E0261` (a malformed character literal) ([Core language](docs/lang/CoreLanguage.md#character-literals)).
- Value inequality, `a !== b`: `!(a === b)` as one token at the level of `===`, building the same image; like `===` it forms no comparison chain ([Core language](docs/lang/CoreLanguage.md#expressions)).
- Inclusive ranges, `0 ..= 9`: the range that contains its stop, with the typing, step, braces and failures of `..`; a range ending at its type's maximum never computes a value past it, and a whole-domain range fails as an over-long `..` range does. New diagnostics `E0262` (a `..=` statement whose destination is not a string, or that has a step) and `E0263` (a range with a third bound or with `..=` and `..` mixed) ([Collections](docs/lang/Collections.md#ranges)).
- String chains, `"Hello, " .. name .. "!"`: `..` with a `string` first operand joins text in written order; every operand must be a `string`, adjacent literals fold at compile time, and `+` is unchanged. A chain of *k* operands allocates its result once and copies each byte once, through the new NeuraIR 1.15 operation `concat text` (op 73) and the NVR 1.9 state operation `concat-text` (op 35); images that use no chain keep their format version and bytes. New diagnostic `E1100` (a chain operand that is not a string); `E0263` also covers a step, braces or `..=` on a chain ([Core language](docs/lang/CoreLanguage.md#string-chains)).
- Escapes: string, interpolated-string and character literals share the escapes `\n`, `\r`, `\t`, `\0`, `\\`, `\'`, `\"`, `\xHH` and `\u{H}` (one to six hexadecimal digits). In a string `\u{1F600}` writes the code point as UTF-8 and the bytes of `\x` escapes must form valid UTF-8 (`"\xC3\xA9" == "é"`); in a character literal `\u{H}` up to `FF` is that byte. New diagnostics `E0268` (malformed `\u` escape), `E0269` (a surrogate or a value above U+10FFFF) and `E0270` (a string whose escapes are not valid UTF-8) ([Core language](docs/lang/CoreLanguage.md#escapes)).
- `typeof(value)` and `typeof(Type)` return a `Std.Reflect.Core.TypeInfo` record (`kind`, `name`, `qualified_name`; value equality with `===`), with the new modules `Std.Reflect.Core.TypeInfo` and `Std.Reflect.Type.TypeKind`. A class or interface reference and an `any` are described by the class of the value they hold (nil is kind `Nil`), every other value by its static type, and a type in a generic function by its type argument. The description is made of program constants, so it works in images without names or a source map; NeuraIR 1.15 operation 74 (`type of`) is expanded at specialization and adds no NVR operation. New diagnostic `E0267` ([Core language](docs/lang/CoreLanguage.md#typeof)).
- `return if (c) -> a; else if (d) -> b; else -> c;` returns the value of the first arm whose condition holds, and `return value unless guard;` returns unless the guard holds (also over a whole `return if` or `return match`); both build the image of the `if` statements they stand for, and `unless` stays an ordinary name elsewhere. Arms written as blocks wait for the lifetime milestone. New diagnostic `E0264` ([Core language](docs/lang/CoreLanguage.md#return-forms)).
- The `..=` statement, `line ..= name .. "!";`, appends text to a `string` binding, field, element or property, evaluating the place once and running a getter and a setter once each; an unparenthesized chain on the right joins after the old value. An integer destination or a step is `E0262`, and a non-string right operand `E1100` ([Core language](docs/lang/CoreLanguage.md#expressions)).
- `match.is (subject) { arms }` selects an arm by the type of the subject's value: a type, `name: Type`, `nil` or `_`, with guards. New diagnostics `E0230` (malformed `match.is`) and `E0490` (a pattern that cannot match) ([Types](docs/lang/Types.md#matchis)).
- Optional access `a?.b` and `a?.m(x)`, which give an `Optional` and skip the rest when the receiver is absent, and coalescing `a ?? b`. New diagnostics `E0233`, `E0494` and `E0495` ([Core language](docs/lang/CoreLanguage.md#optional-access-and-coalescing)).
- The postfix `?`, which returns the error of a `Result` from the enclosing function. New diagnostics `E0232`, `E0496` and `E0497` ([Errors](docs/lang/Errors.md#propagation-with-)).
- The type `any`, packed where it is expected and read with `is` and `match.is`, now executes as typed value words. NeuraIR 1.12 records type kind 13, operations 66 to 68, and returns inside scoped values. New diagnostics `E0492`, `E0493` and `E0498` ([Types](docs/lang/Types.md#the-type-any), [NeuraIR format](docs/NirFormat.md#revision-112-matching)).
- The language server and `neura fmt` handle the new forms: spacing, completion after `?.` and in `match.is` arms, a fix that adds a final `_` arm, and hovers and renames of pattern bindings.

- The runtime service `neurad`, opt-in per launch ([runtime service](docs/runtime/Service.md)): `neura run --runtime=auto|required` runs an image through a per-user supervisor that keeps one worker process ready and the image bytes cached, starting it on demand, with the output, status and traps of a direct run; `--detach --stdout=FILE --stderr=FILE [--stdin=FILE]` and `--runtime-report=FILE`; `neura runtime start`, `status`, `ps`, `inspect`, `stop`, `shutdown`, `enable`, `disable` and `cache clear`; tool statuses 5 (the service ran nothing) and 6 (the outcome is unknown). `--runtime=off`, the default, and `neura test` and `neura debug` run directly as before. `neurad` is the `service` install component, which a plain `cmake --install` leaves out. Linux is tested; macOS is not. On a build with GPU support a launch needs `--gpu=off` or `NEURA_GPU=off` to run through the service. A warm launch is not faster than a direct run on the machine measured (1.32 ms against 0.92 ms for hello-world); the service is for managing processes.
- `neura capabilities --json` has a `service` member: whether `neurad` is installed, its protocol, and whether the installation can use it.
- A tool for each command beside `neura` ([tools](docs/lang/Tooling.md#tools-and-the-neura-dispatcher)): `neurac` (`build`, `check`, `emit-ir`; `neurac app.nra -o app.nvr` builds), `neura-run`, `neura-test`, `neura-inspect` (`inspect`, `inspect-image`), `neura-doc`, `neura-cbind`, `neura-decompile`, `neura-asm`, `neura-disasm`, `neura-explain`, `neura-tags`, `neura-debug`, `neura-lsp`, `neura-fmt`, `neura-doctor`, `neura-update` and `neura-uninstall`. Each takes the options of its command, prints what `neura <command>` prints, and answers `--help` and `--version`. The tools share two libraries in `lib/neura`, `libneura-core-<version>` and `libneura-sdk-<version>`, which they find relative to their own executable; `neura-run` and the other core tools load only the core library.
- Install components: `cmake --install build --component core` installs the execution core only (`neura`, `neura-run`, `neura-inspect` and the lifecycle tools), `--component sdk` adds the rest, `--component service` holds `neurad` when the build has it, and `-DNEURA_SDK=OFF` builds the core without the compiler or the libclang submodule.
- Two products and three archives per target ([Install](docs/Install.md#install-from-a-release-archive)): `neura-sdk-<version>-<target>.tar.gz` (`core` and `sdk`), `neura-runtime-<version>-<target>.tar.gz` (`core` and the service), and the legacy `neura-<version>-<target>.tar.gz`, the SDK's tree under the name 0.2 clients update to. Each archive carries a manifest for each component, `share/neura/components/<name>.txt`, listing its tools and every file with its mode, SHA-256 and size. A release publishes `neura-components.txt` beside `neura-release.txt`.
- The installer links every tool of the installation in the bin directory, installs one generation per build and set of components under `versions/<version>+<id>`, and checks every file against the manifests. `install.sh --add <dir>` installs the SDK and runtime archives as one generation; the one-line command takes `--components sdk|runtime|sdk,service`.
- `neura update --components`, `--rollback`, `--repair` and `--migrate-install`, and `neura uninstall --component sdk|service` and `--terminate` ([Install](docs/Install.md#update)). Every change takes the installation lock and a journal, and an interrupted one is completed or undone by the next command.
- The runtime service across a change ([runtime service](docs/runtime/Service.md#across-an-update)): `neura update` tells the supervisor of the generation it replaced that it is retired, and that supervisor and its workers hold their generation until their applications end; `neura uninstall` is refused while applications of the service run, unless `--terminate`, and stops a supervisor that runs none.
- Generations in use: every tool holds a shared lease on its generation while it runs, so an update leaves editor sessions, debug sessions and running applications on their generation, which is removed by the first change after they end. The previous generation is kept, so `--rollback` needs no download.
- `neura doctor` names the state of the installation (complete, unmigrated, interrupted, damaged) and reports its components from their manifests, the integrity of its files, the service, its links and its generations. In an installation without the SDK it says that source commands need Neura-sdk and omits the SDK's checks.
- NVR 1.8 class hook operations: the state operations `hook-enter` (33) and `hook-leave` (34) keep a per-task stack of open class hook events, with the traps `class hook recursion` (status 134), `class hook nesting limit exceeded` (139) and `invalid class hook operation` (132); tiers 2 and 3 run their blocks at tier 1; the assembler and decompiler read and write them ([format](docs/runtime/NVR.md#class-hooks-18)). The writer emits 1.8 only for an image that uses them.
- Class hook events: after specialization the build derives each read and admission of a policy-carrying reference (`elaborate_class_hooks`), checks that a hook cannot use the scheduler (`E0544`) and that no host binding, kernel or foreign function takes or returns such a reference (`E0546`), records the hook fact in the effect summaries, and checks `#Pure` again with each clause's effects. The optimizer never removes, merges, hoists or inlines an event. Programs without a clause are unchanged.
- Class hook clauses, `| get: ...;` and `| set: ...;` after the `(` of a declared class, are parsed, checked and written to `.nir` (NeuraIR 1.11, attributes `hook.get`, `hook.set` and `hook.of`), formatted, and shown by the language server ([design](docs/design/Hooks030.md#class-hook-clauses)). New diagnostics `E0215`, `E0216`, `E0538` to `E0543` and `E0545`. Executable images use NVR 1.8 for class events. A nil admitted under a class policy carries that policy through storage, calls and checked casts. Programs without a clause keep their `.nir` and image bytes.
- Startup blocks: `static scope { ... }` among a file's top-level statements or a module's members runs once per execution, at its place in source order among the file's initializers, before `main` ([Modules](docs/lang/Modules.md#startup-blocks)). New diagnostics `E0217` (malformed block), `E0218` (block outside a file or module) and `E0470` (`return` in a block). The language server lists each block in the outline as `static scope`. Programs without a block keep their image bytes.
- Payload enums with eligible payloads support `===`, `equals`, `hash_code` and `to_string`. Records can store them, including `Optional` of a record. Named variant fields print in declaration order and their schema travels in NeuraIR 1.13 when needed. [Value members](docs/design/Records030.md#value-members)
- Records: `let User = record (id: int64, name: string);` declares a final, deeply immutable class with one `export last` field per component, a generated constructor, and generated `equals`, `hash_code` and `to_string` (the hash formula of a tuple, the text `App.User(id: 7, name: Ada)`), which carries the NeuraIR attributes `class.record` and `generated`. A record cannot yet hold a payload enum. New diagnostics `E0570` and `E0571` ([Types](docs/lang/Types.md#records)).
- Copy construction, `new with(user) { name: "Grace" }`: the source once, a nil source trapping before any replacement, the replacements in written order, and one allocation that shares the source's children. New diagnostic `E0572` ([Types](docs/lang/Types.md#copy-construction)).
- Interface properties, `let name: string;` followed by `| get;` and optionally `| set;` in an interface, satisfied by exported fields through generated adapters or accessors, and read and written through interface-typed receivers and bounded type parameters. New NeuraIR attribute `property.requirement`, new diagnostic `E0573` ([Polymorphism](docs/lang/Polymorphism.md#interface-properties)).
- Virtual accessors, `| get.virtual:` and `| set.virtual:`, overridden in a subclass with `export let.override name: T;` and `| get.override:`, inside which the property's name calls the base's accessor. New NeuraIR attribute `accessor.virtual`, new diagnostics `E0574` and `E0575` ([Polymorphism](docs/lang/Polymorphism.md#virtual-accessors)).
- Static interface requirements, `static let zero = func() -> T;` in an interface, implemented by a class's own exported static functions and called in generic code as `T.zero()`, which specialization turns into a direct call. New NeuraIR operation `conformance call` (operation 69, format 1.13) and attribute `static.implements`, new diagnostics `E0576` and `E0577` ([Polymorphism](docs/lang/Polymorphism.md#static-interface-requirements)).
- `Std.Core.Arithmetic` with the contracts `Additive`, `Multiplicative`, `Ordered` and `Parseable`, which the primitive companions implement; the integer and float companions gain `zero`, `add`, `one` and `multiply`. New diagnostic `E0578` for a conformance that a module other than a trusted companion declares ([Stdlib](docs/lang/Stdlib.md#66-arithmetic)).
- Derived JSON codecs: `let UserJson = derive json.Codec<User> { field User.name: "display_name"; };` generates a module of ordinary functions, `to_json`, `encode`, `from_json` and `decode`, each returning a `Result`, for an acyclic record or enum, with exact integers of every width, finite floats, `Optional` record fields that are omitted when `None`, and `json.codec.*` errors that begin with the JSON path. `neura check --show-derived[=Name]` prints the expansion, which compiles in its place. The new trusted module `Std.Encoding.JsonCodecSupport` holds the scalar conversions; programs that do not derive build the same images. New diagnostics `E0318`, `E0319`, `E0579` and `E0590` ([Types](docs/lang/Types.md#deriving-a-json-codec)).
- The language server renames a record field with its constructor labels and copy replacements, and pins the old wire name of a renamed field or variant in a derivation that did not; it completes a record's fields inside `new with(source) { }`, also while the copy is unfinished, and its hover shows a record's generated members and a derived module's expansion. `neura docs` lists records with their components and constructor, derived modules with their functions, and static functions as `static` ([Tooling](docs/lang/Tooling.md)).
- `defer call;` runs one call when its block is left, by any exit; the callee, receiver and arguments are evaluated at the statement, and a block's deferred calls run last first, before its `scope` joins its tasks. New diagnostics `E0219`, `E0471` and `E0472` ([Core language](docs/lang/CoreLanguage.md#defer)).
- `using (name = value) { ... }` closes a `Std.Io.Closeable` resource on every exit from its block: a failed close is combined with a returned value by `Closeable.release`'s rule, and returned from the function on any other exit. The resource may not leave the block, judged with the retention summaries of the linked program. New diagnostics `E0220`, `E0473`, `E0474` and `E0475` ([Core language](docs/lang/CoreLanguage.md#using)).
- Generators, `iterator(parameters) -> T { ... yield value; ... }`, functions that return a lazy `Std.Collections.Sequence<T>`: the first `has_next` runs the body to its next `yield`, and the state lives in a generated class. New diagnostics `E0221`, `E0222`, `E0476`, `E0477` and `E0478`; a binding named `yield` in a generator body is `E0311` ([Core language](docs/lang/CoreLanguage.md#generators)). The iteration contract now says that every iterator's `has_next` consumes nothing and repeats no work ([Stdlib](docs/lang/Stdlib.md#54-iteration)).

### Changed

- A scope-bound value, a `Task<T>` or a `Scope`, is no longer converted to `class`, to an interface or to `any`, by assignment, an argument, `as`, or an untyped variadic argument: `E0605` ([Types](docs/lang/Types.md#scope-bound-types)). No source in the repository did so.
- `any` is a reserved type name: no class, interface, enum, module, alias or type parameter takes it (`E0311`); functions, fields, parameters and locals named `any` keep their meaning.
- A `.nir` file that uses `any` or a return inside a scoped value is NeuraIR 1.12; the reader accepts 1.0 through 1.12, and every other program is written as before.
- An unqualified name as the whole pattern of a match arm is `E0412`, with the qualified spelling, where it was `E0304`.
- `record`, `with`, `virtual` and the clause forms are contextual: `new with(...)` always begins a copy, so a class named `with` is no longer constructed by `new with(...)`, and `let x = record(count: limit);` is a record; a call of a function named `record` with a named first argument, written as the whole initializer of an unannotated declaration, is written `(record)(count: limit)` ([Types](docs/lang/Types.md#records)). An accessor clause on an interface method is `E0518`, as on any method, instead of `E0519`, since an interface may declare property requirements.
- The integer and float companions' new `add` and `multiply`, and every companion's `zero` and `one`, shadow extension functions of those names on primitives. Their declarations renumber the `$closure` classes of an image that loads a companion, so the `NAME` section of such an image changes while every other section keeps its bytes.
- The parameter names of an override, and of a method that implements an interface method, are those of the method it replaces (`E0560`), and so are its defaults (`E0561`), because a call may name them. The standard library's `ArrayList.add_all` and `LinkedList.add_all` now name their parameter `items`, as `MutableCollection.add_all` does.
- `nameof` is reserved: no declaration may take the name (`E0311`).
- A call of a generic function that writes no type arguments is no longer `E0417`: it infers them, and is `E0419` when it cannot. Written type arguments are still all or none.
- `E0407` names the first parameter that a call leaves without a value.
- `neura fmt` spaces the `:` of a conditional expression or of a range's step inside an argument list, which it used to glue to the value before it.
- The install marker `neura-install.txt` is schema 2 (`bin`, `components`, `generation` and `link` lines); schema 1 is still read. A tool that reads the marker should read the `link` lines instead of the one `link` path.
- `install.sh` runs the archive's own `bin/neura-update --install-from`, which does every check, the locking and the journaling. It refuses to replace any path in the bin directory that is not one of its links, listing every such path and changing nothing.
- `neura update` reads `neura-components.txt` and installs the same components in the newer version; a release that has only `neura-release.txt` is up to date when it is not newer, and otherwise reports `release <version> has no component metadata`. Old generations are no longer removed at once: `neura update --repair` removes those no one uses.
- From 0.2: `neura update` (with `--nightly` to reach a candidate from 0.2.1-rc.3), then `neura update --migrate-install`. Until the migration, every command works through `neura` and the tools run directly, `neura doctor` fails on `migration`, and updates refuse with the instruction ([From 0.2](docs/Install.md#from-02)).
- `make-archive.sh` takes `--product sdk|runtime|legacy` and one prefix per component in place of one prefix; `make-release-metadata.sh` requires the three archives of each target and writes both metadata files; `qualify.sh` takes the three archives and checks the 0.2 bridge with `--bridge` and the size budget with `--size-reference`.
- `neura` is a dispatcher: it answers `--version`, `help` and `capabilities --json` itself and starts the tool of every other command from the directory of its own executable, never from `PATH`. Every command keeps its options, output, images and exit status. A missing tool is an error before the command starts, naming the component that supplies it; `capabilities --json` reports a feature whose tool is missing as `false`; a tool started by a `neura` of another build refuses to run. A release archive holds every tool in `bin/` and their libraries in `lib/neura`, and a script or package that copies `bin/neura` alone must copy the tools and `lib/neura` with it.
- `neura runtime` is reserved for the runtime service component and reports that the component is not installed, instead of reporting an unknown command.
- The server host's request deadline (S-8) runs from the end of the request head for the worker too, not from the end of the body; S-7 bounds only a complete (buffered) response body; the `Head` frame of the worker protocol carries the body length, and a `Call` can carry a metric. A ready worker that has ended before taking its request is replaced, once.
- A `neura-server-host` worker now holds its S-1 slot until the host has reaped it, so exited workers count against `--max-workers`; the host waits on each worker's `pidfd` instead of polling. With `--max-queue 0` a request that follows a response at once can be refused while the previous worker exits.
- `neura.http.server.body.read` waits for the client's next bytes and fails when the body cannot be read to its end.
- `neura.entropy.fill` reads only the operating system's cryptographic generator and fails with code 100 when it cannot, instead of falling back to `std::random_device`.
- Primitive references borrow local or explicitly owned storage. A borrow of a local or value parameter cannot escape, and accessing an instance-field borrow after destroying its owner traps. Escaping capturing lambdas use `new func`. Escaping bound methods use `new bound(receiver.method)`.

- Local arrays use lexical regions and count against the stack-cell limit. Fresh array results transfer to the caller. An array that escapes its owner produces E0451. Use an explicitly constructed list for storage that must outlive the activation.

- Tuples are stored inline. A tuple is a run of value words, one for each element with nested tuples flattened, wherever it is stored or passed: a frame slot, a parameter, a result (NVR 1.7 result words), a field, a global, a closure capture, an array or list element (an NVR 1.7 aggregate element, so `read-component` and `write-component` reach one word of an element), and a payload of a payload enum (several fields of its object). Copying a tuple copies words, and `t[i]` over a local or a field reads only the words of that element. Where the runtime carries one word, the tuple is boxed in its heap layout before and unboxed after: a task's result and `join`, a channel message, a guard's state, a parallel item's result, a host call's argument and result, a host callback, the pair `string.from_utf8` returns and a kernel's outcome. Output, exit status and trap text do not change, nor do the results of `equals`, `hash_code` and `to_string`. The images of programs that use a tuple change: a function that returns one, or an array or list of them, makes the image NVR 1.7, and an image that uses none keeps its bytes. Steps and `peak_heap_cells` drop where a tuple was allocated only to be passed or read (the `json` benchmark of the standard library loses 2.0 percent of its steps and 4.0 percent of its peak heap cells, and `time-text` 1.1 percent of its steps) and rise where a whole tuple is read from a field, a global or an element, which costs one state exit for each word, or crosses a boundary above. A trap that names a handle number (`invalid reference handle: handle N`) names a smaller number where tuples are no longer allocated, and a `--max-steps` trap that lands inside such code can name another column of the same line. Tiers 2 and 3 run these words, results and components themselves ([Backend](docs/Backend.md#tuples-and-enums-are-words)).
- Payload enums are stored inline, as tuples are. A value is a `uint32` tag and its payload words, pooled by type so that variants share words (`Optional<int>` is two words and `Result<int>` eight), wherever it is stored or passed: a frame slot, a parameter, a result, a field, a global, a closure capture, an array or list element, and inside a tuple or another enum. A word that the variant does not use holds zero, nil, the empty text or the nil collection; `Optional` and `Result` over a payload that needs no allocation allocate nothing, and a match reads the tag and the bound payload's words. Where the runtime carries one word (a task's result, a channel message, a select's send and join arms, a guard's state, a parallel item) the enum is boxed, one field for each word. Output, exit status and trap text do not change. Every program image is now NVR 1.7, because `Std.Program.ExitCode`, which has `Status(int)`, is a payload enum of two words that `main` returns. Seven of the nine benchmarks of `tests/benchmarks` take 11 fewer steps and up to 9 fewer peak heap cells, since the exit code is no longer allocated and read; `json` takes 3.0 percent more steps and 11.1 percent fewer peak heap cells than after the tuple change above (0.9 percent more steps and 14.7 percent fewer peak heap cells than 0.2.1), because a `JsonValue` is five words, read with one state exit each from a list element, and no longer an object; `time-text` takes 0.4 percent fewer steps and 1.7 percent fewer peak heap cells ([Backend](docs/Backend.md#tuples-and-enums-are-words)).
- `E0448` is enforced: an enum that contains itself, directly or through tuples and other enums, is an error at the variant whose payload closes the cycle, and the fix holds the link in a class or a list ([E0448](docs/diagnostics/E0448.md)). The regular expression parser's internal `Node` holds its `Repeat` and `Group` items through a `NodeLink` class. `E0449` now counts a payload enum's words as well as a tuple's.
- Native executables carry the stack cell limit of storage regions: `neura build --native --max-stack-cells N` records it, `NEURA_RUN_OPTIONS=--max-stack-cells N` lowers it, and `neura inspect` prints it on the `limits:` line. `build --native` now writes container version 3, whose policy ends with the limit; launchers still read versions 1 and 2, which run with the default of 16,777,216 cells ([Standalone](docs/lang/Standalone.md#5-the-container)).
- A list is constructed with `new`: `new([1, 2, 3])` where the list type is known from context, `new int[list]([1, 2, 3])` with the type written, `new` alone for an empty list, and `new(0 .. count)` from a range. A bare list literal or range where a list is expected is the new error `E0450`, and `neura check --fix` inserts the `new` and keeps the literal, its comments and its order. A bare literal where an array is expected is still an array. Each form lowers to the NeuraIR that its literal lowered to, so images are unchanged. The standard library, the examples and the tests are migrated.
- `Error.Context` and `PortableError.Context` hold their cause through a link class, `Std.Core.Error.ErrorLink` and `PortableErrorLink` (`#Immutable`), instead of holding the error itself: an enum is about to be stored inline, and an enum that contains itself has no finite size. Code that matches `Context { message, cause }` and uses `cause` as an error reads `cause.cause`; building a context with `Errors.context`, and the results of `message`, `root_cause`, `chain`, `equals`, `hash`, `to_portable`, `from_portable` and `Closeable.release`, are unchanged. Each context costs one more allocation ([Stdlib](docs/lang/Stdlib.md#63-error)).
- Speed on x86-64 Linux, with native tier 3 now the default: the 17 programs of `tests/bench-wall` at their long sizes (`scripts/bench-wall.py --long --runs 5`, median wall time, OpenJDK 21 on the same 8-core machine, every output identical to Java's) take 3.8 times as long as their Java counterparts as a geometric mean, against about 55 times with `NEURA_TIER3=off`, the earlier default. By program: dispatch 1.2, collatz 1.3, mandelbrot 1.4, fannkuch 2.3, spectral-norm 2.3, hash-map 2.6, matrix-multiply 2.8, sort 2.8, sieve 3.0, closures 3.8, object-churn 5.8, sha256 5.9, string-building 6.5, nbody 8.8, parse-results 9.0, text-split 10.3, binary-trees 17.5. The 0.2.1 goal of 2 times as a geometric mean, and at most 3 times for every program, is not met by this candidate ([benchmarks](docs/Benchmarks.md)).
- Native code for tier 2 regions now computes `float32` and `float64` arithmetic, comparisons, and conversions with the processor's scalar instructions instead of calling the runtime for each operation (x86-64 and AArch64). Results are bit for bit those of the reference evaluator, including canonical NaNs; only speed changes ([native compilation](docs/runtime/NVM.md#native-compilation)).
- The overflow proof that lets a block run as native operations is about three to four times faster: the analysis keeps the results of enumerations it has already made, re-evaluates only the nodes an assignment changes, and no longer rebuilds its bookkeeping for every wire. It proves exactly what it proved before.
- Blocks of `float64` squaring, multiplication by a constant, subtraction of a constant, and division by a converted integer are now proven and run as native operations; in 0.2.0 their proof failed with "an output lane not proven 0 or 1" and they stayed on the reference evaluator, which held `nbody`, `mandelbrot`, and `spectral-norm` there for most of their time. The proof of a `float64` or `int64` multiplication or division also takes about a tenth of the time. The circuit library now records which gadget built each neuron while a block is regenerated, and the overflow analysis tries the cut that gadget's own argument uses first. The record is advice: every range is still established by evaluating over all assignments of a cut ([execution tiers](docs/runtime/NVM.md#execution-tiers)).
- The compiler records lift hints for the blocks it builds itself, which in 0.2.0 had none and so ran on the reference evaluator however often they ran: the narrowing of a length to `int32`, the loops of the functions generated for concatenation, text hashing, and value members, value equality of integers, `hash_code` of a Boolean, integer, or float, and the nil tests before a value member is dispatched. With them, 4% to 10% of the steps of the map, text, closure, and dispatch benchmarks move off the reference evaluator. The `LIFT` section gains two operator codes for this, 23 (`-~`, subtraction without an overflow check) and 24 (`hash`). The section stays optional and never trusted, and every other byte of an image is unchanged. A 0.2.0 runtime reads a section that uses either code as malformed and ignores it whole, as the format prescribes for hints it cannot read, so such an image runs there correctly and without hints ([lift hints](docs/runtime/NVR.md#lift-hints), [backend](docs/Backend.md)).
- A block with a lift hint is now proven after it has run 4 times instead of 256, and its proof may use about 16 ms of work at the first attempt. Proofs became cheap enough that waiting cost more than proving: the float benchmarks at their full sizes take about a third to a half of the time they took with the old thresholds. Which blocks run lifted, and when, changes; nothing a program can observe does ([execution tiers](docs/runtime/NVM.md#execution-tiers)).
- The runtime stores each heap entry as one block, with array and list elements at the width of their element type (one byte for `bool` and `uint8`), and a garbage collection visits only the handle pages that still hold a live entry instead of every page the run has created. Peak memory falls where collections are narrow (`binary-trees` at full size 174 to 64 MiB), and collection cost no longer grows with the number of objects a run has ever allocated (instructions spent collecting in `text-split` at ten times its full size fell from 10.8 billion to 1.4 billion). Nothing observable changes: outputs, traps, `steps`, and `peak_heap_cells` are the same.
- A garbage collection now marks an object's fields, and an array's or list's elements, from first to last, so it walks the heap in the order the program allocated it, and it finds which fields hold references through a table instead of a hash map. On `binary-trees` the time spent collecting fell from about 630 to about 240 milliseconds over the same 100 million steps. It marks exactly the same entries, so nothing observable changes.

### Fixed

- In a build with GPU support, `neura test` with the default `--gpu=auto` (and `neura run --each`) could run many times slower than with `--gpu=off` when auto mode never used a device: a file of 17 Unicode property tests took over five minutes instead of 21 seconds, and reported `gpu: auto, not used (the workload cannot gain)`. While auto mode weighs a device, the tests run as a fleet that steps every block on the reference evaluator, and after it gave the device up the fleet kept doing so to the end, without execution tiers or native code. A fleet now stops offering jobs once its device declines every job, and its members, which share the command's tier cache, continue at their tiers: the same file takes 22 seconds. A fleet with more members than its window (4,096) steps its started members at tier 1, without regions, until the last ones start. Results, step counts and the `gpu:` line are unchanged; `--tier-stats` now reports the tiers a fleet used. The gate's cost before it gives a device up is unchanged ([GPU execution](docs/lang/GpuExecution.md#105-advance)).
- `neura-server-host` no longer spins a core while a finished worker exits, and its worker channel never blocks inside `send(2)`, so the request deadline also bounds a write to a worker and a worker that streams a large response before it reads a large request body cannot block the host.
- `neura-server-host` sends each response without waiting about 40 ms for the client's delayed acknowledgement: accepted connections set `TCP_NODELAY`, and a head with a body of at most 64 KiB leaves in one write with it.
- `neura build` rejected a program that specializes one generic function for two classes of the same name from different modules, such as `copy_of_list<Row>` for a program's `Row` and a library's `Row`, with an image loader error (`type N is not assignable to type M`): IRtoNeuronConversion found module functions and methods by name, and both specializations have the name `copy_of_list<Row>`. It now finds the specialization a call names; images of other programs are unchanged.
- A module that overrides `Std.Program.Entry.main` and calls a requirement could not be inherited by the program's module that implements it: the image ran `main` for the module that declares it, and the build failed with an internal error (`E0899`, "module does not implement"). The image now runs `main` for the one module of that line that no other module inherits; two such modules are rejected as two entry points (`E0804`), and a call of a requirement that the module it runs in leaves without a body is `E0434` with a fix, no longer `E0899` ([Modules](docs/lang/Modules.md#interfaces-and-inheritance)).
- `neura fmt` changed code in ways the coding style forbids, and `neura fmt --check` failed on the standard library. It wrote a grouping parenthesis against the operator before it (`a ==(b + 1)`, `return(x)`, `[a],[b]`), split a tag group such as `#[Final, Immutable, Since("0.3.0")]` across lines when a member spanning several lines came before it, joined lines that the source wrapped, put a blank line between a comment and the member it describes, broke a statement at a `,`, joined a `while` statement to the `}` before it, spaced `- x` in `(-x)`, and spaced a member call `arena.scope ()`. It now keeps wrapped lines, tag groups and comments where they belong, spaces parentheses by what they follow, and is idempotent on every `.nra` file of the repository; the standard library and the examples are formatted with it ([Tooling](docs/lang/Tooling.md#editor-tooling-research-candidate)).
- A web bundle's page ran its image under the runtime's default limit of 100,000,000 steps for the whole run, so a page whose updates are heavy stopped with a step-limit trap after a number of interactions (the 1,000-row list of budget B-W5 stopped before its 200 clicks were done). The boot module now runs the image with the largest limit; `NvmExecution`'s `maxSteps` still sets one.
- A view that one UI root refused or only prepared is no longer `ViewReused` in another root; only a view that another root has mounted is.
- An HTML factory may return an element whose required parent is outside the template, such as `<li>` or `<tr>`; it was rejected as `E0243` although the HTML note's own `part_row` example does this.
- `nvm.wasm` lowers binary32 and binary64 operations to the WebAssembly float instructions, as x86-64 and AArch64 do. The lowering used to refuse them on every other platform, so float blocks in a browser ran by reference: `mandelbrot` and `spectral-norm` at their quick sizes went from about 6 s to 1.5 s in Chromium, and the geometric mean of the wall-clock set from 644 ms to 555 ms.
- Images no longer depend on the C++ compiler that built `neura`. The converter and the structural proof built some gadgets (selections, thresholds, signed multiplication, division and remainder, NaN canonicalization, loops bounded by a length) from calls whose order C++ leaves unspecified, so GCC and Clang wrote different graphs for the same source (151 of 186 corpus images differed), and a runtime built by one rejected lift hints of an image built by the other: a Clang-built runtime, as `nvm.wasm` is (Emscripten), rejected 6 of the 16 hints of a GCC-built `collatz`, and 33 of 46 in the new fixture. GCC-built images keep their bytes; the `lift-portable` test pins the graphs of a fixture and requires every hint to lift.
- `neura run --task-dump` wrote the dump twice, the first time naming a block the task had already left, when a check failed inside a tier 2 region (an index out of bounds, for example) and tier 1 ran the block again and trapped. The dump is now written once, when the failure becomes the run's trap, as at tier 0.
- Editor tooling in 0.2.1-rc.2: readable documentation hovers, valid outline names and ranges, completion for declaration modifiers, eligible inherited overrides, promoted exports, import paths and typed/primitive/collection receivers, and quiet formatting of incomplete editor buffers. CLI formatting continues to reject invalid source.
- The website places one skill-copy button above its prompt with feedback that keeps the page in place, keeps the front page's frame fitted during mobile scrolling, and gives diagnostic codes a compact Reading Room overview.
- The compiler no longer reads freed memory while lowering three constructs, which 0.2.0 does: an accessor whose body declares names (the `W0005` and `E0405` messages were built from a freed field name), a generic enum applied to an anonymous class (`Optional<class (...)>.None` with many fields could crash the compiler), and a target-typed `new` of an anonymous class whose field initializer declares many names (it could be rejected with a wrong `E0403` or crash). Programs that compiled are compiled to the same image.
- Three defects of the overflow proof that 0.2.0 has. The proof accepted a graph in which a node reads one wire twice, counting the two edges as the two halves of a step pair; it divided the most negative 64-bit weight by -1, which is undefined; and when a wire's range was 2^63 wide or more it looped over that range without counting the work against its limit. The loader rejects the first kind of graph before any proof, and no graph that the circuit library builds was found to reach the other two, so no image is known to have run wrongly. The proof now refuses a graph whose edges are not in strictly ascending order of source itself, and its arithmetic and loops are bounded on every input ([execution tiers](docs/runtime/NVM.md#execution-tiers)).
- With `NEURA_TIER_PROGRAMS=1` (or `NEURA_TIER3=interp`), a block whose call, list or array literal, or other operation took more than 255 arguments read only the low 8 bits of the count, so it ran with too few arguments: a 300-element list literal built a list of 44 elements. Such a block now runs on the reference evaluator. The default configuration was not affected.

## [0.2.0] - 2026-11-11

This version adds assign-once `last` bindings, target-typed `new`, anonymous classes in type positions, accessors on exported fields, and `#` tags to the language; requires a `;` after every declaration; gives every diagnostic a code, a rendered source snippet, and a page that `neura explain` prints; runs parts of the standard library on built-in C kernels; and adds two execution tiers above the reference evaluator: blocks proven to compute typed operations run as native operations, and regions of them run together, as machine code the runner generates on x86-64 Linux. The standard library is rewritten in the new style, and some of its zero-argument methods are now fields. The [release checklist](docs/Release.md) maps each feature to its tests.

### Migrating from 0.1.0

- **Semicolons.** Every declaration now ends with `;`, including a function, overload group, class, interface, or module whose body ends at `}` or `)`. A 0.1.0 source that omits one fails with `E0201`. `neura check --fix <file.nra>...` inserts every missing `;` in place and then checks the result. Statement blocks (`if`, `while`, `for`, `match`, `scope`, `select`, and a bare `{ }`) still take none.
- **Standard library fields.** Members that only returned stored state are now fields, read and assigned without parentheses: `buffer.size()` becomes `buffer.size`, `logger.set_level(LogLevel.Debug)` becomes `logger.level = LogLevel.Debug`, and `stream.set_read_timeout(d)` becomes `stream.read_timeout = d`. The full list is under [Changed](#changed). A call with `()` on one of them is `E0423` (`expression is not callable`), and an assignment to a read-only one is `E0510` or, for a `last` field, `E0445`.
- **Diagnostic format.** Errors are now printed with a code, the source lines, and labels, over several lines. A script or test that matched the 0.1.0 line `file:line:column: error: message` should pass `--error-format=short`, which prints that line with the code added (`file:line:column: error[E0201]: message`) and is the stable form; `--error-format=json` gives one JSON object per diagnostic.
- **Warnings.** The standard library marks I/O results, resource handles, and value-returning queries `#NoDiscard`, so a call whose result is dropped, such as `file.write(bytes);`, now warns with `W0003` (`unused-result`). Use the result, or discard it on purpose with `let _ = file.write(bytes);`. `-Wno-unused-result` turns the warning off, and `-Werror` turns warnings into errors.

### Added

**Language**

- `last` bindings: `last x = value;` binds `x` once, like a local `const`, and `last x: T;` declares it without a value; it is then assigned exactly once on every path before it is read, which the compiler checks with a definite-assignment analysis (`E0440` to `E0447`). An instance field declared `last` is assigned by its initializer or exactly once by every `init`. `last` is a contextual word: it declares only when an identifier follows it, so a binding named `last` keeps working ([Core language](docs/lang/CoreLanguage.md#source-and-bindings), [Object lifecycle](docs/lang/ObjectLifecycle.md#last-fields)).
- Target-typed `new`: `let a: Point = new;` and `= new(arguments);` construct the type that the context expects, in a binding or field annotation, an assignment, a `return`, a call argument, an element of a typed collection, and either arm of a conditional. `let a = new;` without an expected type is `E0420` ([Object lifecycle](docs/lang/ObjectLifecycle.md#target-typed-new)).
- Typed and listed destructuring: `let [a, b]: [K, V] = e1, e2;` gives each name its own value and its element of the annotation as the expected type, evaluated left to right (`E0436`, `E0437`) ([Types](docs/lang/Types.md#typed-and-listed-destructuring)).
- Anonymous classes in type positions: `let p: class (export let x: int = 0;) = new;`. A body of plain exported typed `let` fields is one class wherever it is written, identified by its fields; a body with a method, a base, a `const` or `last` field, an accessor clause, or a tagged member is a class of its own at that spot (`E0530` to `E0536`) ([Types](docs/lang/Types.md#anonymous-classes)).
- Accessors on exported instance fields: `| get: expression;` and `| set: statement;` (or a block) after the field. Code outside the class reads `object.field` and assigns `object.field = value` without call syntax and goes through the accessors; inside the class a bare name is the storage. A get-only field is read-only outside its class (`E0510`), a set-only field write-only (`E0515`); `E0516` to `E0524` give the other limits ([Types](docs/lang/Types.md#accessors)).
- `#` tags before declarations, class and module members, enum variants, and parameters: `#Name`, `#Name(arguments)`, and `#[A, B]`. The registry holds 85 tags. Implemented: `Deprecated`, `Experimental`, `Internal`, `Hidden`, `NoDiscard`, `Final`, `Sealed`, `Inline`, `NoInline`, `Allow`, and `Deny`, and the checked tags `Pure`, `Immutable`, `ThreadSafe`, `NotThreadSafe`, and `Synchronized`. Seventeen informational tags, such as `Since`, `Note`, and `Unit`, are recorded and shown by `neura docs`. The other 52 are reserved, and using one is `E0908`, which names what to write instead. Tag errors are `E0900` to `E0922` ([Tags](docs/lang/Tags.md)).
- Monitors: a class whose exported methods are all `#Synchronized` and whose state only its own methods reach may be shared between tasks; each synchronized method runs under a per-instance guard, first come, first served, re-entrant for calls on its own receiver. Instances of `#Immutable` classes may also be shared between tasks ([Concurrency, section 8.1](docs/lang/Concurrency.md#81-monitors)).
- `#Pure` is checked (`E0917`) in every specialization of a generic function and over every dispatch target, including interface implementations and the `to_string`, `hash_code`, and `equals` that value text, hashing, and equality call. A kernel call writes the lists it is given to fill or sort. A pure function may pass an object it allocated to a helper that writes only its parameters.
- `#Immutable` (`E0918` to `E0920`), `#ThreadSafe` (`E0608`, `E0609`), and `#Synchronized` (`E0921`, `E0922`) are checked by the compiler.
- `#NotThreadSafe` on a class keeps its instances in one task: a task may create and use its own, and giving one to another task is `E0602`. On a function or method it rejects a spawned task or parallel worker that can reach it (`E0601`). A `#NotThreadSafe` class cannot also be `#Immutable`, `#ThreadSafe`, or a monitor (`E0907`, `E0610`).

**Diagnostics**

- Every compiler error has a code, `E0101` to `E0916`, by area: `E01xx` lexer, `E02xx` parser, `E03xx` names, `E04xx` types and bindings, `E05xx` classes and lifecycle, `E06xx` concurrency, `E07xx` modules and imports, `E08xx` backend, and `E09xx` tags. Warnings are `W0001` `deprecated`, `W0002` `experimental`, `W0003` `unused-result`, `W0004` `inline`, and `W0005` `setter-never-stores`. There are 164 codes, each with a page in [`docs/diagnostics`](docs/diagnostics/README.md) that states the rule and shows a failing and a fixed program ([Tooling](docs/lang/Tooling.md#diagnostics)).
- `neura explain <CODE>`, `neura --explain <CODE>`, `neura explain <warning-name>`, and `neura explain --list` print those pages, which are built into the binary.
- Rendered diagnostics: the source lines with the primary span marked `^` and secondary labels marked `-`, across lines and files, then notes and a `help:` with the edited line. Common errors label the code that explains them and suggest a fix: the declaration of a constant that is assigned, the earlier of two duplicate declarations, the closest name to an unknown one, the origin of an expected type, the missing arms of a `match`, and a missing `.override`.
- `--error-format=human|short|json`, `--color=auto|always|never`, `--max-errors N` (default 20), `-W<name>`, `-Wno-<name>`, `-Werror`, and `--warn-library`.
- The lexer and the parser recover from an error and report several per run, in source order.
- `neura check --fix` applies every machine-applicable suggestion to the source files and checks the result.
- `neura tags` prints the tag catalogue and `neura tags <Name>` one tag; `neura docs` shows the tags, `last`, and accessors (`{ get; set }`) of each declaration and leaves `#Hidden` declarations out.

**Runtime and standard library**

- Built-in C kernels: 67 deterministic, pure C functions that the runtime calls in place of standard library code, each with the replaced Neura code kept as its test oracle. A trusted `Std` module binds one with `kernel("name", version)` ([Kernels](docs/runtime/Kernels.md), [Standard library, P2a](docs/lang/Stdlib.md#p2a-kernel-bindings-in-source)). A kernel call is charged steps in advance by a formula over its arguments, is not a host request, and needs no capability.
- Kernel-backed modules: `Std.Digest.Sha256` and `Crc32`; every function of `Std.Math.Math`, bit for bit as before; in `Std.Text.Strings` the searches, comparisons, trims, `split`, `split_limit`, `lines`, replacements, ASCII case mappings, `scalar_count`, and `hash`, and the `String` members built on them; `StringBuilder.hash_code`; the integer companions' `to_string_radix` and `parse_radix`; and `Std.Encoding.Utf8.validate`, `Base64`, and `Hex`. Their results, errors, and traps are unchanged; their step counts are lower.
- `Std.Collections.Sorting.sort_ascending` sorts a list of `int32`, `uint32`, `int64`, `uint64`, or `float64` values on a kernel.
- Execution tiers: tier 0 evaluates every block by reference; tier 1 runs a block as native operations once the runner has proven that its graph computes typed operations whose overflow checks and results match the reference, floating-point addition, subtraction, multiplication, and division of `float32` and `float64` included; and tier 2, the default, runs regions of proven blocks of one function together, without returning to the step dispatcher, and goes back to tier 1 at any block that traps, calls, allocates, or reaches a limit. The result, steps, traps, output, and traces are the same at every tier ([NVM](docs/runtime/NVM.md#execution-tiers)). `neura run` and `neura test` take `--tier=0|1|2` and `--tier-stats`; `NEURA_TIER` lowers the tier for every run, `NEURA_TIER_CHECK=1` checks every tier-1 step against the reference and every region against tier 1, and `NEURA_RUN_OPTIONS` may lower the tier of a native executable.
- Native code for tier 2 regions: the runner compiles each region of proven blocks to machine code, which runs in place of the region interpreter with the same exits, slots, traps, steps, output, and traces ([NVM](docs/runtime/NVM.md#native-compilation)). `neura run`, `neura test`, and `NEURA_RUN_OPTIONS` take `--jit=off|on|auto`, and `NEURA_JIT` sets it for every run; `auto`, the default, compiles on x86-64 Linux, and `on` also compiles on AArch64 Linux, AArch64 macOS, and x86-64 macOS, or fails the run at its start where it cannot. `--tier-stats` reports the regions compiled, their bytes of code, the entries that ran native code, and the regions left on the interpreter and why. Code is mapped writable, then executable, never both, and `--deny-native` does not turn it off.
- The optional `LIFT` section of an image records the typed operations of each block for tier 1. The runner proves each one and never trusts it. `neura build --no-lift-hints` leaves it out.
- IR optimization passes: copy propagation, common-subexpression elimination including reuse of pure calls, loop-invariant hoisting, dead-store removal, removal of unused pure calls, and inlining of small calls, which `#Inline` and `#NoInline` direct. An optimized program never takes more steps, heap cells, or frames than the unoptimized one ([IR optimization](docs/IrOptimization.md)).
- New standard library fields: see [Changed](#changed).

**Formats and tools**

- NVR 1.6: the `KERN` table of kernel records and the kernel state operation (24). Only an image that calls a kernel is written as 1.6 ([NVR](docs/runtime/NVR.md#kernels-16)).
- NeuraIR 1.10: symbol attributes (tags, accessors, `last`, anonymous classes, kernel bindings, inlining directives, synchronized methods, and shareable classes) and deferred initialization. A program that imports the standard library, whose declarations carry tags, is written as 1.10 ([NeuraIR format](docs/NirFormat.md#revision-110-symbol-attributes-and-deferred-initialization)).
- `scripts/bench-wall.py` and `tests/bench-wall/`: a wall-clock benchmark harness of twelve programs, each with a Java counterpart, and `--compare-tiers` ([Benchmarks](docs/Benchmarks.md)).
- `tests/ui/` and `scripts/ui-test.py` (the `ui-<area>` tests) compare rendered diagnostics and applied fixes with snapshots, and `scripts/check-diagnostics.py` checks that every diagnostic has a registered code, a page, and a test.
- The language skill for AI agents covers the new syntax, the tags, and the diagnostics, and its examples use the modern style.

### Changed

- Every declaration ends with `;` (`E0201`, fixed by `neura check --fix`). In 0.1.0 a declaration whose body ended at `}` or `)` could omit it.
- The default diagnostic output is the rendered `human` form described under Added. The 0.1.0 one-line form, with the code added, is `--error-format=short`.
- A task-safety error keeps its first clause and names the function that breaks the rule; each call on the way, the offending operation, and the place a library starts the task are labels instead of text in the message.
- Standard library members that are now fields (old → new):
  - `Std.Core`: `StringBuilder.byte_length()` → `byte_length`; `IntRange.start()`, `end()`, `step()` → `start`, `end`, `step`.
  - `Std.Text`: `Regex.pattern()`, `group_count()` → `pattern`, `group_count`; `RegexMatch.start()`, `end()` → `start`, `end`.
  - `Std.Io`: `ByteBuffer.size()` → `size`; `BufferedWriter.buffered()` → `buffered`.
  - `Std.Fs`: `Path.is_absolute()` → `is_absolute`; `FileMetadata.kind`, `size`, and `modified` are read-only (`last`) fields.
  - `Std.Net`: `TcpListener.local_port()` → `local_port`; `TcpStream.set_read_timeout(d)` → the field `read_timeout`, assigned `stream.read_timeout = d`, whose setter traps on a negative duration as before and whose getter returns the duration last set.
  - `Std.Log`: `Logger.set_level(level)` → the field `level`, read and assigned `logger.level = level`.
  - `Std.Time`: `Instant.epoch_seconds()`, `nanos()` → `epoch_seconds`, `nanos`; `LocalDate.year()`, `month()`, `day()` → `year`, `month`, `day`; `LocalDateTime.date()`, `time()` → `date`, `time`; `ZoneOffset.total_seconds()` → `total_seconds`; `Stopwatch.is_running()` → `is_running`.
  - `Std.Math`: `BigDecimal.unscaled()`, `scale()` → `unscaled`, `scale`.
  - `Std.Concurrent`: `Parallel.ItemLimits.max_steps` and `max_heap_cells` are read-only (`last`) fields.
- The standard library is written in the modern style: assign-once values are `last`, constructions whose type is named by an annotation use `new` alone, every module carries `#Since`, value and resource classes are `#Final`, and I/O results, resource handles, `Result` and `Optional` queries, and other value-returning calls are `#NoDiscard`, so dropping one warns `W0003`. The scheduler's `select` protocol members are `#Hidden`.
- The standard library marks the classes whose instances hold mutable or native state `#NotThreadSafe`: `StringBuilder`, `Regex`, `Random`, `Logger`, `Stopwatch`, `FixedClock`, `ByteBuffer`, `BufferedReader`, `BufferedWriter`, `Utf8Reader`, `Utf8Writer`, `File`, `TcpStream`, `TcpListener`, the mutable collections (`ArrayList`, `ArrayDeque`, `LinkedList`, `HashMap`, `HashSet`, `StringMap`, `IntMap`, `OrdinalMap`, `TreeMap`, `TreeSet`, `PriorityQueue`, `BitSet`, `Sequence`), and `Arena`, `MemorySegment`, `MethodHandle`, `Linker`, and `SymbolLookup`. Giving one to another task or sending one on a channel was already `E0602`, because none of them is transferable; the error now also points at the tag, and a task may still create and use its own and return one to the task that joins it. `#Pure` now also marks the functions that build their result in a `StringBuilder` or list of their own, such as `Json.parse` and `write`, `Csv.write`, the float `parse`, `to_fixed`, and `to_exponential`, `Regex.compile`, and the `BigInteger` arithmetic ([Stdlib](docs/lang/Stdlib.md#58-task-safety)).
- Text searches use a linear algorithm and are charged steps by the text they can reach, so a long needle no longer makes a search quadratic, and `replace_first` no longer charges for every possible occurrence.
- A program that imports the standard library is written as NeuraIR 1.10 by `neura emit-ir -o`; a 1.9 reader cannot read it.

### Removed

- `Logger.set_level` and `TcpStream.set_read_timeout`, replaced by the fields `level` and `read_timeout`, and the zero-argument methods listed under Changed, replaced by fields of the same name.

### Fixed

- `Std.Digest.Sha256` and `Crc32`, and the `Std.Encoding.Hex` and `Base64` decoders, keep no module state any more, so a spawned task or a parallel item may call them.

### Known issues

- Sustained computation is not yet near the speed of a compiled or JIT-compiled language. In one local measurement on x86-64 Linux at the quick sizes the tiers ran ten of the twelve benchmark programs 1.1 to 48 times as fast as tier 0 and `nbody` and `spectral-norm` slower (see the proving cost below), and at the full sizes `nbody` (2,500 steps) still took 6.3 s and `spectral-norm` (64) 11.7 s. The time goes to blocks that stay on the reference evaluator, to calls, allocations, and other exits that regions do not run, and to proving blocks ([Benchmarks](docs/Benchmarks.md)).
- There are no measured comparisons with Java yet. `tests/bench-wall/` has a Java counterpart for each program, but the machine where the harness was run had no JDK, and the Java programs have not been compiled.
- Proving a block that multiplies or divides `float64` values takes a few tenths of a second, and the runner spends that time while the program runs. A float-heavy program that ends within a second or two can therefore take longer than at `--tier=0` (in one local measurement, `nbody` and `spectral-norm` at their quick sizes took about 1.2 times as long); longer runs repay the proofs. Blocks that compute `float16` or `bfloat16` values stay on tier 0.
- A synchronized method re-enters its guard only for calls on its own receiver. Calling back into the same instance any other way, such as through a function value that captured it, while the guard is held traps with `invalid state: guard already held`.
- A monitor cannot hold a list or a map in a field directly, because every field of a shared class must have a transferable type; keep the collection in a `Guarded<T>` field or with an owner task.
- An accessor cannot satisfy an interface member, and accessors cannot be overridden, so the collections keep `size()` and `is_empty()` as methods.
- `LocalTime.hour()`, `minute()`, `second()`, and `nano()` remain methods, because they are computed rather than stored.
- Tags cannot precede a statement or a destructuring declaration (`E0909`).
- Native code for tier 2 regions is verified by execution only on x86-64 Linux. On AArch64 (Linux and macOS) its instruction encodings are checked against an assembler's, but the generated code has not been run, and the macOS memory mapping (`MAP_JIT` on Apple silicon) has not been run either, so `--jit=auto` interprets regions there and `--jit=on` is experimental. The `Native code` workflow runs the comparison on those platforms; it is not yet required.
- Lexical and syntax errors are reported several at a time, but name resolution, type checking, and the later checks stop at the first error.
- The two known issues of 0.1.0, `neura run --each` with `--gpu=always` on an image whose tasks wait on cancellable host I/O and the `neura-libclang-load` test on Linux arm64, are not addressed in this version.

### Changed

- `neura run`, `neura test`, and the policy that `neura build --native` records now grant every host service by default: files, network, environment, clock, entropy, and native code. Before, each needed its `--allow-*` option. Run an image you do not trust with `--deny-all` and the `--allow-*` options it needs. The capability options now apply in command-line order, so `--allow-fs --allow-fs=prefix` grants only the prefix.
- A collection's `to_string` prints `(this collection)` wherever its own text reaches it again, including through other collections. An indirect cycle used to end with the frame-limit fault.
- The trap for denied native access reads `native access denied: the native capability is not granted`.
- A program that uses a scope, a channel, or another scheduler operation cannot also use `Std.DynamicForeign` or `import:c(...)`.

### Fixed

- The install script and `neura update` treated a `gh` that is installed but not signed in as a failed provenance check and stopped. They now report that provenance was not verified and continue, as they do without `gh`; `--require-attestation` still stops. Found by the release workflow on the candidate `v0.1.0-rc.1`, whose published `install.sh` has this defect; `0.1.0` does not.

### Known issues

- `neura run --each <file> --gpu=always` does not finish for an image whose tasks wait on cancellable host I/O, such as `tests/concurrency/io/cancelled.nra`; the same fleet finishes with `--gpu=off` and with the default `--gpu=auto`. [GPU execution](docs/lang/GpuExecution.md) specifies that a fleet gives the results of running its members in order, so this is a defect, not a documented limit. The release archives are built without the GPU backend and are not affected; a build from source with the backend is.
- On Linux arm64, `neura-libclang-load`, a test of the `neura-libclang` submodule, fails because it expects `char` to be signed. C imports themselves map `char` as the platform does.

### Security

- A native executable finds its own file through `/proc/self/exe` or the path the kernel recorded, never through its program name, and writes traces through an exclusively created temporary file. `--trace-events` refuses a symbolic link at its path.
